# Принятые решения

Дата: 17 ноября 2026 года.

1. Рабочая папка Site была пуста. Поиск среди существующих соседних проектов не выявил приложения с этим назначением. Новая отдельная папка: `agent-workspace`. Старые проекты не изменялись.
2. Python в PATH на этом компьютере оказался недоступен; Node.js 24.22.1 и встроенный SQLite доступны. Поэтому сервер использует только стандартные модули Node, а интерфейс — HTML/CSS/JavaScript. Установка сторонних пакетов и сборщик не нужны.
3. Приложение локальное. Облачная публикация, регистрация Sites и передача рабочих данных внешним сервисам не выполнялись.
4. 2ГИС Places API подключается на сервере, только при ключе и явном подтверждении права на долговременное хранение, обработку и экспорт. Стандартная оферта справочного WebAPI ограничивает такой сценарий (п. 3.1). Без нужных прав — ручной помощник и импорт разрешённых данных. Это ограничение подтверждения, а не юридическая проверка договора программой.
5. Контактные поля требуют отдельного доступа. Их получение выключено по умолчанию. Отсутствующий сайт в ответе API никогда не приводит к автоматическому отрицательному заключению.
6. Отрицательный результат проверки сайта оформляет пользователь, предоставляя два источника, обоснование, фактическую дату и отметки проверки карточки/независимого поиска. История доказательств сохраняется отдельно от пользовательских заметок.
7. Дополнительные агенты имеют отдельные конфигурации, списки файлов и собственную историю. Общий настроенный модельный сервер не получает никаких инструментов. Подключение к базе компаний требует явного разрешения агента.
8. Без модели доступен честно обозначенный сбор материалов без анализа. Создание агента по обычному описанию заполняет форму, не расширяя права. ИИ включается только при настройке провайдера и разрешении агента.
9. Приостановка отменяет запрос; возобновление разрешает новый ручной запуск. Долговременной очереди исполнения в первой версии нет.
10. Для пользовательского удаления агента используется архивирование. Компании не удаляются: неподходящие можно пометить. Исходные и рабочие файлы задачи не удалялись.
11. XLSX формируется стандартным OOXML в ZIP без сторонних зависимостей; CSV — UTF-8 с BOM. Потенциальные формулы в CSV обезвреживаются, XLSX использует inline strings.
12. Проверки производятся в отдельных временных SQLite-базах. Фиктивные компании не добавляются в рабочую базу.
